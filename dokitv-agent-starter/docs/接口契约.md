# 首期接口契约 v0.3（HTTP 兼容扩展 v0.1/v0.2）

## HTTP

开发地址 `http://127.0.0.1:8201`。所有接口需 `Authorization: Bearer <credential>`。
demo 凭证为 demo-alice 和 demo-bob；这些只是本地协作身份，不是生产认证。

| 方法与路径 | 输入 | 输出 |
|---|---|---|
| POST /api/agent/runs | JSON：`{"message":"查询视频1001昨天的弹幕数"}` | 202 + Snapshot + Location |
| GET /api/agent/runs/{runId} | UUID | 200 + Snapshot |
| GET /api/agent/runs/{runId}/events | 可选 Last-Event-ID 事件序号 | text/event-stream |
| POST /api/agent/runs/{runId}/cancel | 无请求体 | 200 + Snapshot |
| GET /api/agent/runs/{runId}/evidence/{evidenceId} | 证据 ID | 200 + Evidence |

message 不得为空，最长 2000 字符。任务和证据只对创建者可见，读取时重新检查身份范围。
如果资源范围发生收缩，旧任务会拒绝读取，直到明确实现更细粒度的结果过滤。
服务端每次创建任务生成 UUID，暂未实现请求去重；重复 POST 会创建独立任务。

Snapshot（Java record 字段名即 JSON 字段名）：

```json
{
  "runId": "00000000-0000-0000-0000-000000000001",
  "status": "SUCCEEDED",
  "createdAt": "2026-10-20T00:00:00Z",
  "steps": 3,
  "traceId": "32 lowercase hex",
  "answer": {"text": "【模拟数据】...", "evidenceIds": ["ev_example"]},
  "clarification": null,
  "errorCode": null
}
```

响应头增加 X-Trace-ID；任务 Snapshot 的 traceId 对应创建时的 Trace。其他读取请求可拥有自己的 HTTP Trace。
Trace 与 Hook 的扩展契约见《Harness-Trace与Hook设计》。

状态为 QUEUED、RUNNING、SUCCEEDED、NEEDS_INPUT、FAILED、CANCELLED。
最后四种为终态；终态不可再被晚到的模型响应覆盖。
NEEDS_INPUT 表示本次任务已经结束。首期由前端把原问题和补充信息合并成新请求，不提供隐式会话记忆或任务恢复。

HTTP 层身份/请求错误直接返回非 2xx；异步执行错误写入 FAILED 状态及 ERROR / DONE 事件。
不要只通过创建接口的 202 判断任务成功。

## SSE

事件体统一为 `sequence / type / data / at`。SSE 的 id 与 sequence 相同，从 1 递增。

```text
id:1
event:PROGRESS
data:{"sequence":1,"type":"PROGRESS","data":{"run_id":"...","stage":"queued"},"at":"..."}
```

| 事件 | data | 行为 |
|---|---|---|
| PROGRESS | stage、可选 tool | 展示进度，不承诺输出内部推理过程 |
| CLARIFICATION | message | 请求补充信息，随后 DONE |
| ANSWER | text、evidenceIds | 已经过首期引用归属校验的最终答案，随后 DONE |
| ERROR | code | 执行失败，随后 DONE |
| ABORT | reason | 用户取消，随后 DONE |
| DONE | run_id、status | 每任务唯一终态事件 |

首期没有 ANSWER_DELTA、ARTIFACT_READY；新增这两类事件前先明确校验和交付时序。
同进程内可使用 Last-Event-ID 重放未读事件。游标小于 0 或超过当前序号会被拒绝。
断线后任务继续运行，需要主动调用 cancel 才取消。
默认内存存储重启后回放与状态均不可恢复；前端必须处理 RUN_NOT_FOUND。

浏览器原生 EventSource 无法直接设置自定义 Authorization 头；当前前端使用 fetch 流读取，并自行管理
Last-Event-ID 和重连，或由后续统一登录方案提供同源安全 Cookie。不要把 Bearer 凭证放到 URL 查询串里。

## 模型与工具

`ModelPort` 收到 ModelContext：message、businessDate、AccessScope、activeSkills、observations、availableTools、remainingSteps。
availableTools 包含工具描述与 JSON Schema；真实适配器应转成选用模型的工具调用协议。
模型只返回一个 Decision，三选一：

- TOOL：ToolCall(name, arguments)。由 Runtime / Dispatcher 执行。
- CLARIFY：clarification 非空。
- ANSWER：Answer(text, evidenceIds)。不能引用当前任务不存在的证据。

工具注册与执行校验均在 `ToolDispatcher`；全局工具与当前激活 Skill 的工具分别暴露。

| 工具 | 参数（只接受列出的字段） | 返回 |
|---|---|---|
| list_skills | `{}` | 名称、描述列表 |
| read_skill | `{"name":"video-metrics"}` | 完整 Skill 与工具 Schema，并激活工具 |
| read_result | `{"result_id":"ev_..."}` | 当前任务拥有的结构化证据 |
| query_video_metrics | `{"video_id":1001,"date":"2026-10-19","metric":"bullet_count"}` | 指标值、版本、来源、数据时间、证据 ID |

query_video_metrics 必须先激活 video-metrics；日期限定北京时间最近 30 个已结束自然日。
AccessScope 是服务端内部参数，不在模型可填写的工具 Schema 中。
当前失败策略为 fail-fast：参数、权限、工具调用错误立即结束；暂未实现模型自我修复和自动重试。

## 业务查询契约

`BusinessQueryPort.query(MetricQuery, AccessScope)` 接收 videoId、date、metric。
真实适配器必须在业务查询服务端再次校验权限，不能只依赖 Agent 的前置检查。
返回 MetricData：

| 字段 | 含义 |
|---|---|
| videoId / date / metric | 必须与本次请求相符 |
| value | 指标数值；无数据覆盖时不能伪装成 0 |
| metricVersion | 统计口径版本 |
| source | 可识别的数据来源 |
| dataAsOf | 数据覆盖/同步水位；不能随意用当前请求时间替代 |
| timezone | Asia/Shanghai |
| complete | 对请求时间范围是否完整；首期不完整结果会拒绝交付 |
| demo | 是否为合成数据 |

当前 demo 适配器始终返回 128 和 synthetic-fixture，dataAsOf 是合成快照的生成时刻。
真实适配器应建立正确的水位语义；不能复用演示中的 Instant.now() 实现。

ToolDispatcher 登记 Evidence(id, runId, owner, data)。ID 是引用句柄，不是授权令牌。
当前实现验证引用存在且属于任务/用户，尚不能保证文字结论与每个数值、比较关系、因果描述相符。
同学实现真实模型后，必须扩展 AnswerVerifier 或限制为基于结构化指标的模板渲染。

## 错误码

| 类型 | 代表码 | 处理 |
|---|---|---|
| 身份 / 范围 | UNAUTHORIZED、FORBIDDEN | 不重试，重新登录或检查范围 |
| 查询与状态 | RUN_NOT_FOUND、RESULT_NOT_FOUND | 检查过期、重启、所属任务 |
| 输入 | INVALID_REQUEST、INVALID_ARGUMENTS、DATE_OUT_OF_RANGE | 修改请求或工具参数 |
| 能力 | TOOL_NOT_AVAILABLE、SKILL_REQUIRED、SKILL_NOT_FOUND、TOOL_NOT_FOUND、METRIC_UNSUPPORTED | 修复模型路由或能力配置 |
| Hook | HOOK_REJECTED、HOOK_TRANSFORM_FAILED、HOOK_TRANSFORM_INVALID、HOOK_PAYLOAD_TOO_LARGE | 排查策略/变换插件，不自动交付原始数据 |
| 执行 | NO_PROGRESS、STEP_LIMIT、DEADLINE_EXCEEDED | 查看任务轨迹，调整任务或预算 |
| 结果 | INVALID_DECISION、INVALID_ANSWER、INVALID_EVIDENCE | 拒绝交付，排查适配器 |
| 资源 / 内部 | CAPACITY_EXCEEDED、QUEUE_FULL、INTERNAL_ERROR | 调查容量或内部实现；不返回敏感异常 |

## 并发、部署与扩展限制

执行池核心 2、最大 4、队列 32；任务容量 200。这些是本地协作的资源上限，不是吞吐承诺。
运行时每步检查 30 秒墙钟时间；这不是远程 HTTP 的硬中断机制。
SSE 推送当前是同步写，慢客户端可能延缓 worker；正式部署需独立发送队列与背压策略。
尚无多副本任务归属、事件共享、持久化和水平扩展机制；第一期保持单实例部署。
后续生产配置必须替换 demo 身份、只读凭证、调用超时、限流、持久化和审计。
