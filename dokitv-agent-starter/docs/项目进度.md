# DokiTV Agent 基架项目进度

更新：2026-10-22。当前交付版本 v0.7.0-SNAPSHOT。

## 当前进度

存储已从设计落到真实适配器：MySQL 正式记录、Redis 近期会话视图、私有文件对象和统一终态事务已接通。默认仍可离线演示；启用 persistent profile 后，服务重启可以查询任务、消息、事件、证据和产物。

这是独立 Agent 基架工程，业务身份和指标仍来自 demo，尚未接入 DokiTV 正式查询。存储联调使用隔离数据库，没有改动现有业务库。

## 已完成

| 模块 | 实际能力 | 当前边界 |
|---|---|---|
| 原有基架 | Skill/Tool/Prompt 文件目录，注册与 Schema，PreparedTask、Hook、OTel、Kafka/file Trace、循环控制 | 单 Agent、串行工具，复杂分析/RAG 未实现 |
| MySQL | Flyway 迁移，九张业务表，run/消息/事件/证据/产物元数据/澄清/审计/outbox | 需专用库，显式启用 persistent |
| 唯一终态事务 | 终态、助手消息、ANSWER/CLARIFICATION/ERROR/ABORT + DONE、审计和 outbox 原子提交 | 提交后更新内存；网络投递仍需按事件序号去重 |
| 会话 | sessionId/turnSeq、正式消息分页、近期历史投影、当前问题边界 | 通用指代理解未做全面评测 |
| 澄清续接 | replyToRunId 一次消费，新 run 合并已确认条件；原相对日期固定 | 内置仅单视频弹幕条件 |
| 幂等 | 拥有者范围内 Idempotency-Key 唯一，重复内容返回原任务，不同内容 409 | 保留期内保证，不是永久去重 |
| Redis | 有界问答窗口、版本条件更新、权限范围指纹、TTL、失败回源 MySQL | 当前适配单节点/单入口；无 Cluster/Sentinel/TLS 装配 |
| 对象存储 | ObjectStore 端口与私有文件适配器；原始证据 JSON、归属、哈希、长度、READY 状态 | 没有 S3/MinIO SDK，当前只读 JSON 对象 ≤1 MiB |
| 重启恢复 | QUEUED 重新调度；RUNNING → RUNNER_LOST；完成任务直接回放 | 不重放中间步骤；未实现执行检查点 |
| 并发治理 | 同会话新任务取代旧任务；数据库写实例锁、generation 和状态检查 | 每个数据库一个写实例，不支持多写实例并行调度 |
| 清理与审计 | 会话删除禁读、异步对象/数据库清理、到期数据和未完成上传清理 | 当前保留期为初始固定策略；未测生产吞吐/恢复目标 |
| 模型 | 可选同 Key 的 Flash 预处理/V4 Pro 主模型，受控调用次数预算 | Token/金额账本仍待实现；本次未调用收费模型 |

## 验证

全量 106 项自动化测试通过，失败/错误/跳过均为 0，包括 6 项真实 MySQL、2 项真实 Redis 测试。历史 Unicode 边界调整后，又通过 6 项定向边界测试。

真实 MySQL 验证覆盖：SQL 故障时整笔终态事务回滚、消息/事件/审计一致性、幂等冲突、范围收缩、证据/对象重建、第二写实例拒绝、RUNNER_LOST 和旧 writer 拒绝、删除与对象清理。

实际 JAR 的进程级验证结果见 [验证记录](验证记录.md)。真实业务数据、真实 Kafka 正向消费、Linux Redis 7.4/MySQL 8.4、S3/MinIO、多实例部署和压力测试未完成。
