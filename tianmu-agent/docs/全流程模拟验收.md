# 全流程模拟验收

本脚本从真实 HTTP 接口提交请求，启动打包后的 Java 服务，通过本地 HTTP 模型模拟器执行预处理和 Harness，使用真实 MySQL、Redis、私有文件产物和文件 Trace。模型与业务指标为模拟数据，外部模型调用次数为 0；本验收不代表真实模型能力或正式业务 SQL 已通过验证。

## 运行准备

需要 JDK 17、Python 3.10+、MySQL 命令行客户端，以及隔离的本机 MySQL 和 Redis。Python 脚本只使用标准库。先执行 `mvn -B package` 生成 Agent JAR。

测试数据库名称必须以 `_it` 结尾，MySQL 和 Redis 均使用本机地址。脚本不停止已有数据库服务，不清空已有表；每轮生成独立会话，仅删除自己创建的主验收会话。Flyway 会在该测试库创建和验证 Agent 表。

通过环境变量提供 `AGENT_JDBC_URL`、`AGENT_DB_USER`、`AGENT_DB_PASSWORD`、`AGENT_REDIS_HOST`、`AGENT_REDIS_PORT`，可选 `AGENT_REDIS_PASSWORD`。MySQL 账号需要正常 Agent 迁移和读写权限。不要使用正式业务数据库。

在 Agent 模块目录运行：

```powershell
python scripts/simulate_flow.py `
  --jar target/operations-agent-0.7.0-SNAPSHOT.jar `
  --output-dir ./var/simulation-20261022
```

`--output-dir` 必须是尚不存在的目录。可通过 `--java`、`--mysql-client` 指定可执行文件路径；也可以用 `--env-file` 指定私有 JSON 配置文件，字段名与上述环境变量相同。凭证文件放在仓库外，不提交 Git。

脚本强制将模型地址设为本地模拟服务器，使用占位凭证；不使用环境中的付费模型地址和 Key。模拟模型沿用项目的 JSON 决策协议，实际调用模型适配器、Skill 和 Tool，不替换 Agent 主循环。

## 主场景

1. 请求“你能做什么”，FAQ 直接回答，不调用模型。
2. 在同一会话请求“查询视频1001的弹幕数”，系统要求补充日期。
3. 带 `replyToRunId` 回复“昨天”，消费一次澄清状态。
4. 一次问题理解完成澄清判定、条件提取与 Query 改写，同时并行情绪识别；条件校验通过后进入 Harness，正常预处理共两次模型调用。
5. Harness 调用 `read_skill`，再调用 `query_video_metrics`，最后引用证据回答。
6. 用户收到标明“模拟数据”的 128 条弹幕；正式消息、唯一终态事件和审计提交 MySQL，证据原文保存到私有文件，Redis 刷新近期问答窗口。
7. SSE 实时交付后按事件游标回放；进程重启后仍能读取任务、历史和产物。

## 额外场景

- 无凭证、跨用户读取和越权视频查询被拒绝；模型自己生成的越权工具参数也被拒绝。
- 同一幂等键复用原任务；同键不同内容、重复消费澄清返回冲突。
- 理解结果的改写缺失或擅自更换视频时保留原查询；理解调用失败或提取条件与原问题冲突时追问，不进入 Harness。
- 非中性情绪与合法改写能进入准备结果；慢情绪识别不阻塞主查询。
- 非法模型决策、模型超时、在途取消产生受控且唯一的终态。
- Redis 暂时不可用时，下一轮从 MySQL 获取已有历史并继续回答。
- 删除会话后立即禁止读取，随后清理数据库记录与私有对象。
- 同一请求的准备、模型、工具和结束记录可用同一个 Trace ID 串联。

## 结果文件

输出目录含 `report.json`、三次应用启动日志、Trace 归档、私有对象目录和 Java 临时目录。只有检查实际执行且断言通过，才写入对应的 PASS；未完成或失败的整轮报告为 FAIL，并保留已通过的检查和错误原因。

当前验证范围不包含真实业务数据、付费模型效果、Kafka Broker 正向生产消费、S3/MinIO 或多实例调度。进程重启覆盖完成任务回放；在途任务恢复和事务回滚另由真实 MySQL 集成测试验证。
