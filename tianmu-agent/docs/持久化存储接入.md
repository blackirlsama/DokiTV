# 持久化存储接入：v0.7

更新：2026-10-22。本页描述实际代码；更完整的目标架构见 [存储体系设计](存储体系设计.md)。

## 当前接通的内容

- MySQL：真实保存会话、请求/PreparedTask、用户/助手消息、事件、证据、产物元数据、澄清状态、审计和 outbox。Flyway 执行版本迁移并校验校验和，重启不清库。
- Redis：Lettuce 连接真实 Redis，缓存有界近期问答窗口；版本条件写防止旧视图覆盖新视图；不可用时回源 MySQL。缓存键包含当前授权范围指纹，权限收缩后不能复用旧范围的历史视图。
- 对象：ObjectStore 已有真实私有文件实现。当前指标证据也保存一份完整 JSON 对象，读取验证归属、长度、SHA-256；模型事实仍从结构化证据获得。实现 ObjectStore Bean 可以替换对象后端，S3/MinIO SDK 适配器尚未提供。
- 交付：终态、助手消息、终态事件/DONE、审计和 outbox 同一 MySQL 事务提交。失败回滚后内存不发布答案，终态竞争权仍可由后续取消/失败入口处理。
- 连续会话：sessionId、消息序号、近期历史、显式 replyToRunId 澄清续接。准备与主模型接收相同的受限历史视图；焦点规则单独位于 prompts/common/current-focus-boundary.md。
- 清理：删除会话先禁读、终止活跃任务，再异步清理数据库子记录与私有对象；清理过期事件、澄清状态、正式记录及未完成上传。

默认 demo 仍可离线运行。使用持久化必须显式启用 persistent profile；不会在 MySQL 故障时退回内存并报告成功。业务查询仍来自模拟适配器，持久化不改变数据口径。

## 启动

先创建一个专用空 Agent 数据库，提供该库的账号。不要将地址指向 Tianmu 业务库；Flyway 不会对没有版本记录的非空库自动 baseline。

PowerShell，在启动进程中配置：

```powershell
$env:AGENT_JDBC_URL = 'jdbc:mysql://127.0.0.1:3307/Tianmu_agent?serverTimezone=UTC&allowPublicKeyRetrieval=true&sslMode=DISABLED'
$env:AGENT_DB_USER = 'agent'
# AGENT_DB_PASSWORD 由启动环境或凭证管理注入。
$env:AGENT_REDIS_HOST = '127.0.0.1'
$env:AGENT_REDIS_PORT = '6380'
$env:AGENT_OBJECT_DIRECTORY = 'C:\path\to\private-agent-artifacts'
java -jar Tianmu-agent-demo.jar --spring.profiles.active=demo,persistent
```

示例 JDBC 的无 TLS 配置仅用于本机回环开发。正式服务使用对应证书和 TLS 配置；凭证独立注入，不放进 URL、源码或文档。目录须使用绝对路径并保留，以便服务重启后读取已有对象。

真实模型可以启用 demo,deepseek,persistent，模型 Key 继续通过既有环境变量注入。切换正式身份/业务适配器时，使用相应业务 profile，不应依赖 demo 身份。

本地 Docker 环境可使用 [Compose](../infra/storage/compose.yml)：先在环境里注入 AGENT_DB_PASSWORD 与 AGENT_MYSQL_ROOT_PASSWORD，再执行：

```powershell
docker compose -f infra/storage/compose.yml up -d
```

MySQL 使用持久卷，Redis 是可重建缓存。Compose 中的 MySQL 8.4 / Redis 7.4 是部署配置；本机 Docker daemon 未运行，本次没有执行这份 Compose。

## 配置

| 配置 | 用途 |
|---|---|
| AGENT_JDBC_URL | 专用库 JDBC 地址，不能携带 user/password 参数 |
| AGENT_DB_USER / AGENT_DB_PASSWORD | 数据库凭证 |
| AGENT_REDIS_ENABLED | 默认 true；设为 false 时只用 MySQL 构造历史 |
| AGENT_REDIS_HOST / AGENT_REDIS_PORT / AGENT_REDIS_PASSWORD | Redis 地址与可选凭证 |
| AGENT_OBJECT_DIRECTORY | 私有对象目录，默认 ./var/artifacts |

当前 Redis 适配器连接单节点/可用的单一入口；Redis Cluster、Sentinel、TLS 的专用装配尚未实现。池大小、命令超时和窗口上限均有界，未做生产吞吐承诺。

## API 用法

创建新会话的请求省略 sessionId；响应 Snapshot 增加 sessionId、turnSeq。后续请求带返回的 sessionId。

```http
POST /api/agent/runs
Authorization: Bearer demo-alice
Idempotency-Key: example-request-001
Content-Type: application/json

{"message":"查询视频1001的弹幕数"}
```

返回 NEEDS_INPUT 后，使用返回的 sessionId 和 runId：

```json
{
  "message": "昨天",
  "sessionId": "上次返回的会话UUID",
  "replyToRunId": "上次NEEDS_INPUT的任务UUID"
}
```

Idempotency-Key 同一拥有者范围内唯一；相同内容重试返回原任务，内容不同返回 409。UUID 示例需替换为真实值。补充条件创建新任务，沿用原来已确认的条件来源；原问题中的“昨天”按原任务业务日期固定，本轮补充的“昨天”按本轮日期解释。

显式续接当前仅实现已有的单视频弹幕条件，不承诺任意业务的自动追问补全。一般自然语言追问可以获得历史背景，但复杂指代的模型质量仍需评测。

新增接口：

| 接口 | 用途 |
|---|---|
| GET /api/agent/sessions/{id}/messages?before={messageSeq} | 最多 50 条正式消息，按序返回；下一页使用本页最小序号作为 before |
| DELETE /api/agent/sessions/{id} | 202，先逻辑禁读，随后异步删除 |
| GET /api/agent/runs/{id}/artifacts | 本任务 READY 产物的 ID、类型、大小、哈希 |
| GET /api/agent/runs/{id}/artifacts/{artifactId} | 鉴权后读取私有 JSON 对象 |

原 GET run、GET evidence、SSE、cancel 路径保留。SSE 支持重启后按 Last-Event-ID 回放。事件超过保留期返回 EVENTS_EXPIRED/410，可读取最终 Snapshot。

## 提交、重启与并发语义

v0.7 每个数据库只允许一个 Agent 写实例，用数据库会话级锁明确拒绝第二个写实例。该锁在专用连接上维持；失去锁的实例不能继续持久化写入，不自动无条件重新抢锁。尚不支持多个实例并行领取任务。

同会话新消息取代旧任务，递增 generation，旧任务持久化为 SUPERSEDED。API 查询从数据库取正式记录；原 worker 通过检查点或周期同步感知终态并取消调用。

启动恢复：未执行的 QUEUED 请求重新调度，仍受原截止时间和调用上限约束；RUNNING 请求记为 RUNNER_LOST，产生唯一 ERROR/DONE，不自动重放模型/工具。正常关闭尽量持久化 SHUTDOWN。执行检查点、写工具幂等、多实例租约调度属于后续阶段。

Redis 的刷新 outbox 有领取、条件确认、退避重试和 DEAD 状态。当前只有 MEMORY_REFRESH 目标；Trace 继续使用原有 Kafka/file 出口；MySQL 审计已真实落库，但未额外建设 Kafka 审计导出消费者或查询平台。

## 生命周期与实现位置

当前策略初值：正式 run/消息/证据/对象结束后 30 天，会话闲置 30 天，事件创建后 7 天，澄清 24h，审计 90 天，Redis 最长 24h；未完成上传超过 1h 进入清理。新请求不续期所有旧轮次。未发送 outbox 不按普通 TTL 删除。

存储模块位于 adapters/storage，仓储/对象端口位于 runtime/store，历史视图位于 application/MemoryBuilder。MySQL 仓储作为工作单元协调跨表事务，其内部事件与证据适配器复用同一作用域。

实际迁移是 src/main/resources/db/migration/V1__agent_storage.sql，含快照、原始输入、执行 Query 和权限快照字段；[storage-schema.sql](storage-schema.sql) 保留为最初的设计草案，不能当作现行建库脚本再手工导入。

## 验证方式

普通 mvn test 不要求启动数据库；真实集成测试需显式配置 AGENT_STORAGE_IT=true，且 JDBC 库名必须以 _it 结尾，避免将测试连向正式库。

配置独立测试 MySQL/Redis 的上述环境变量后运行 mvn test，可执行真实事务、唯一约束、缓存版本、权限收缩、重建、写实例隔离、对象和删除测试。测试不使用 H2 替代 MySQL。

本次联调使用隔离 MySQL 8.0.44；Redis 协议测试使用 [Redis 5.0.14.1 非官方 Windows 移植](https://github.com/tporadowski/redis/releases/tag/v5.0.14.1)，仅用于本地集成验证。尚未完成 Linux Redis 7.4、MySQL 8.4、S3/MinIO 和多实例的部署验证。最终结果见 [验证记录](验证记录.md)。
