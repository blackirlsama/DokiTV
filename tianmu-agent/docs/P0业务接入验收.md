## 已修复的问题

原消息入库会重新生成 ID，消费者还会吞掉异常。现在沿用入口生成的 ID 与时间，重复投递不重复计数，记录与计数同事务；失败抛给 Broker。测试覆盖并发重复、同 ID 内容冲突、计数失败回滚。

TIMESTAMP 与 DATETIME 分别处理时区，桥接使用私有 UTC 只读连接池，不修改业务写连接池时区。查询在同一 SQL 中检查视频归属与未删除状态。

第一次真实模型结果已成功，但验收脚本对“3条”的文本格式约束过严而误报；修正为数值与证据校验后，重启读取同一已完成任务复核通过，没有为复核重复付费请求。

## 统计口径与未覆盖范围

统计的是指定创建日期、当前已入库且仍保留的弹幕。不是历史发送总量，不含已删除记录，也不保证异步消息全部到达。

测试辅助工具按现有 JwtUtil 签发相同格式的 JWT，再写入在线 Redis；没有执行密码登录 HTTP 页面/接口的完整链路。正式业务账号、现有库正常状态与时区、索引执行计划、MQ Broker 重投/死信、生产吞吐和系统级安全审查仍待完成。真实模型只验证了一个场景，不代表全面准确率。
