# 工程目录与扩展规范

更新日期：2026-10-22，v0.7。

## 1. 目录约定

Java 代码按职责分包；业务说明、模型指令、工具描述分别放在资源目录。一个工具一个实现类，一个 Skill 一个目录，Prompt 按阶段拆文件。

## 2. 新增 Skill

在 resources/skills 下新增一个目录，提供 skill.json 与 SKILL.md。例如复用已注册工具的新查询说明：

```json
{
  "name": "another-analysis",
  "version": "1.0.0",
  "description": "能力的用途和适用范围",
  "tools": ["query_video_metrics"]
}
```

SkillCatalog 启动时发现所有 skills/*/skill.json，读取同目录 SKILL.md。list_skills 与 read_skill 的可选名称随目录自动生成。只复用已有工具时，不需要修改 SkillCatalog、ToolDispatcher 或 AgentRuntime。

Skill 描述的是怎样使用已存在的工具；它不能实现新的 Java 行为，也不能提升用户的数据权限。新工具仍需要注册处理器。名称重复、版本非法、正文缺失或引用不存在的工具，会在启动时拒绝。

## 3. 新增 Tool

1. 增加 resources/tools/<tool_name>/tool.json，填写名称、说明及 inputSchema。
2. 增加一个独立 Java 类，实现 AgentTool 并注册为 Spring Bean。
3. 业务工具保持默认 requiresSkill=true，在对应 Skill 元数据中声明该工具。
4. 工具实现从 ToolContext 获取可信身份、业务日期及受限查询/证据能力，执行后返回 ToolResult。

ToolRegistry 会收集所有 AgentTool Bean，按 order、name 稳定排序，并验证处理器与描述文件一一对应。缺少处理器、缺少描述、重复名称、业务工具未归属任何 Skill，都不能启动。生产装配由 Spring 完成；测试保留独立装配入口。

ToolDispatcher 不包含工具名称的 switch。新增处理器后，不需要到分发器、Runtime 或模型客户端追加分支。read_skill 自己负责从 SkillCatalog 生成动态名称枚举。

当前 Schema 验证器有明确范围：对象参数、全部字段必填、禁止额外字段，字段支持 string/integer，以及 enum、minimum、minLength、date。未实现完整 JSON Schema；声明数组、嵌套对象或其他未支持规则会在启动时拒绝，不能假装已经校验。更复杂参数需扩展公共验证器并补测试。

Schema 在工具调用变换后检查。视频权限、日期范围、查询结果一致性和证据归属继续由固定执行边界及业务工具检查。Java 处理器是可信代码扩展，不能把这些检查交给 Prompt 或 Skill 文案承担。

## 4. 修改或新增 Prompt

修改 resources/prompts 中对应 Markdown；内容有变更时同步更新 index.json 中的版本。新增阶段需要增加索引项并在相应模型适配器中引用 Prompt ID。

索引示例：

```json
{"id":"preparation.emotion","version":"1.0.0","path":"preparation/emotion.md"}
```

PromptCatalog 负责读取和校验，DeepSeekAdapters 只装配 Bean；DeepSeekPreparationModel 和 DeepSeekHarnessModel 负责输入投影与协议解析。模型业务指令不写在配置工厂或 Java 字符串中。收尾指令也由 Harness 从资源读取。

不对用户文本做字符串模板替换或代码执行；用户问题、工具结果作为独立 JSON 数据消息传入。输出协议验证仍在 Java 中执行。

## 5. FAQ 与配置

演示 FAQ 放在 resources/faq/demo.json，包含 id、version、questions、text，由 demo profile 的 ClasspathFaqPort 加载。只做精确匹配，重复问题会拒绝启动；正式知识库需实现 FaqPort，承担授权和审批规则。

模型 ID、地址、连接上限等仍属于 application*.yml 和环境配置。API Key 只通过环境变量注入，不放入 Skill、Tool、Prompt 或 FAQ 文件。

## 6. 加载与交付语义

当前全部采用 classpath 资源，在启动时校验并形成不可变快照；修改文件后需要重新构建、部署或重启，尚未实现远程资源和热更新。Skill / Prompt 显式带版本，源码通过 Git 管理；没有声称已具备远程版本仓库或自动回滚。

加载使用资源流，兼容可执行 Spring Boot JAR，不依赖源码路径或工作目录。读取限制大小、校验 UTF-8、拒绝重复 JSON 字段与缺失资源；Prompt 索引路径不能越出目录。

后续若增加远程加载，应在 Catalog 后增加版本固定的资源提供者，继续复用这些契约与校验。Runtime、Dispatcher 和模型协议层无需读取文件系统细节。

对应测试见 CatalogArchitectureTest；覆盖新增 Skill/Tool 接入、启动拒绝错误配置、不可变快照、Prompt 路径、资源大小/编码和 FAQ 归属。打包后另用 JAR 验证资源发现及演示完整请求。

## 6. v0.6 执行与扩展约定

- 新的确定性前置条件检查实现 QueryReadinessPolicy；新的结构化任务解释实现 TaskSpecificationResolver，均由 Spring 收集，具体业务不写进准备调度器。
- ToolContext 不再提供 RunState/Harness。新增工具通过该接口返回结果，不能直接提交终态、发送 SSE 或任意修改 Skill 集合。查询适配器仍负责真实业务权限。
- PreparedTask 固定原始条件、日期、资源版本、工具上限、总截止时间和调用次数上限，CONTEXT Hook 不能替换任务契约。
- EvidenceStore 保存事实，ExecutionState 维护模型可见观察记录。后续上下文压缩修改视图，不改原始证据。
- 事件存储与 SSE 传输分开，持久化实现需要另行设计状态和事件事务，不能只替换一个类就声称支持多实例。
- StopReason 已移至 core 包；旧 Java 扩展需更新 import。HTTP 状态字符串继续兼容并新增预算耗尽原因。

请求时序、超时与降级以 [统一入口与并行预处理](统一入口与并行预处理.md) 为准。六个 Maven 模块、通用沙箱与持久化执行内核仍是后续演进，当前为分包单体。

## 7. v0.7 存储扩展

- adapters/storage：MySQL 工作单元、RedisMemoryCache、FileObjectStore、持久化 Bean 装配。
- runtime/store：RunRepository、RunBackend、EvidenceStore、ObjectStore 端口；core/MemoryTypes 为不可变历史视图。
- application/MemoryBuilder、ClarificationInputs：模型历史投影与受支持条件合并，不访问传输层。
- resources/db/migration：Flyway 版本迁移；resources/application-persistent.yml：持久化装配。
- resources/prompts/common/current-focus-boundary.md：历史与本轮焦点边界，已进入 Prompt 版本清单。

新增远程对象后端实现 ObjectStore 并注册 Bean；不得让工具接触裸 DataSource 或 Redis 客户端。终态必须经 RunBackend/统一数据库事务提交后再发布，不能用异步 Hook 补存储。
