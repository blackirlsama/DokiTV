# 弹幕分析报告

视频和直播间的弹幕使用同一张 `bullet` 表、同一个 `videoId` 标识和同一套归属权限。意图按任务区分：查询数量使用已有 `VIDEO_METRIC`，内容分析与报告使用 `DANMAKU_REPORT`；不会按“视频”或“直播间”称呼分流。

## 请求与时间范围

向现有 `POST /api/agent/runs` 提交问题，例如：

```json
{"message":"分析视频1001昨天的弹幕并生成报告"}
```

也支持“分析直播间1001昨天的弹幕并生成报告”和“分析videoId=1001昨天的弹幕并生成报告”。`视频ID：1001`、`video_id:1001` 同样使用共同的目标解析器，身份授权、条件提取和澄清续接保持一致。

第一版接受一个目标、一个日期或“昨天”，也接受两个完整日期时间，例如 `2026-10-23 20:00到2026-10-23 22:00`。时间按 Asia/Shanghai 解释，区间为 `[start,end)`，最多24小时，开始日期在最近30天内，结束时刻不得在未来。条件不完整或不合法时在请求准备阶段澄清；“昨天20:00到22:00”等省略形式目前要求补充完整日期时间。

## 端到端流程

1. 沿用身份校验、FAQ 优先短路和三路并行准备；识别 `DANMAKU_REPORT`，服务端解析并固定 `danmaku.report` 任务的 `video_id/start/end`。
2. Agent 调用 `read_skill(name="danmaku-analysis")`，激活弹幕查询与报告工具。`list_skills` 可用于发现能力。
3. `query_danmaku(video_id,start,end)` 调用业务桥接的 `GET /internal/agent/danmaku-analysis?videoId=...&start=...&end=...`。工具参数必须与固定任务一致，模型不能改ID或扩大范围。
4. 后端重新校验身份与 `video` 归属，在只读 REPEATABLE READ 事务中计算统计与有限片段，返回数据集。
5. 数据集存为本次运行的 Evidence，模型只收到统计与最多48条片段；每条片段最多160个字符，不含发送者ID，手机号与邮箱作规则遮盖。
6. Agent 根据片段生成定性观察与建议，调用 `create_danmaku_report(evidence_id,sections_json)`。每条观察必须引用1至4个本证据中的片段ID；错误引用会拒绝。
7. 服务端模板读取原始统计、转义模型和片段文字，生成私有HTML产物，发出 `ARTIFACT_READY`。工具成功后通过统一交付结束本次任务，SSE 仅有一个 `DONE`。

澄清目前属于请求准备流程。实际代码尚未接入参考架构中的 Kflow 灰度回退、RAG 或公开报告短链。

## Tool 与 Skill

| Tool | 作用 |
| --- | --- |
| `list_skills` | 列出可用Skill |
| `read_skill` | 阅读Skill并按声明激活业务工具 |
| `read_result` | 按证据引用读取工具结果 |
| `query_video_metrics` | 原有按videoId和日期查弹幕数量的工具，视频与直播间均适用 |
| `query_danmaku` | 按videoId和时间范围获取准确统计与有限内容片段 |
| `create_danmaku_report` | 校验片段引用、渲染与保存HTML报告，并请求统一交付 |

| Skill | 工具 |
| --- | --- |
| `video-metrics` | `query_video_metrics` |
| `danmaku-analysis` | `query_danmaku`、`create_danmaku_report` |

## 数据口径与限制

SQL 对查询范围内当前仍保留的已入库记录计算 `COUNT(*)` 和非空 `user_id` 的 `COUNT(DISTINCT user_id)`。趋势最多12个等宽时间段，宽度向上取整到秒；空段保留零值。它不代表全部发送数量、在线人数或观看人数。

每段按 `create_time,bullet_id` 取最早最多4条，合计最多48条。这是有偏的非随机片段，只支持举例和定性观察。第一版没有全量语义分类，不输出全量话题/情绪占比、重复率、转化率或因果结论。原始弹幕作为不可信数据，不能充当指令。手机号和邮箱遮盖是有限规则，并非完整隐私识别。

报告统计由模板读取，不由模型填写。语义段落最多6条，通常不超过3条；没有可靠观察时传 `[]`。离线 Demo 使用合成数据和脚本模型，只验证统计、工具、报告、权限与交付流程，不伪造语义分析。启用 DeepSeek 后才由真实模型依据Skill生成片段观察；本轮未执行收费模型评测。

## 报告读取与存储

`ARTIFACT_READY` 和最终回答提供相对地址 `/api/agent/runs/{runId}/reports/{artifactId}`。该地址必须携带 `Authorization: Bearer ...`；前端需通过鉴权请求读取HTML，再渲染到沙箱iframe。直接点击不携带凭据的浏览器链接会返回401，当前未实现前端接入。

读取时重新认证并验证运行归属和当前数据权限。响应为 `text/html;charset=utf-8`，使用 `no-store`、`nosniff` 与沙箱CSP，不执行脚本或加载外部资源。

Demo 用内存保存；persistent 默认复用视频平台的同一MinIO实例，地址和凭据读取 `TIANMU_MINIO_*`，私有bucket默认 `tianmu-agent-artifacts`，前缀默认 `agent-artifacts/`。可用 `AGENT_MINIO_*` 单独覆盖。HTML正文以 `rp_<uuid>.html` 保存；已有 `agent_artifact` 记录归属、对象key、大小、SHA-256与过期时间，经历 PENDING → READY，并写审计。读取经Agent重新授权和完整性校验，客户端不获取MinIO公开或预签名地址。

每份报告最多256KiB，每次运行最多2份；持久化报告跟随原有运行数据到期清理，清理同时删除MinIO对象。HTML正文不进入后续模型上下文，只返回产物引用。显式 `AGENT_OBJECT_STORE=file` 可用于本地开发；已有文件对象的迁移要求见[持久化存储接入](持久化存储接入.md)。

## 业务数据库接入

需要同时构建并更新根工程的业务桥接和 `tianmu-agent`。继续使用现有 JWT/Redis 登录检查、租户和 `video` 归属规则，无需新增报告业务表。`TIMESTAMP` 通过UTC只读连接查询，`DATETIME` 按 `BUSINESS_DATETIME_ZONE` 明确配置存储时区；默认 Asia/Shanghai。

部署前检查 `bullet(video_id,create_time,bullet_id)` 的等价覆盖索引，并对真实数据执行 `EXPLAIN`，确认范围查询和按时间取样的成本。现有InnoDB二级索引若已按 `(video_id,create_time)` 建立且 `bullet_id` 是主键，通常已隐含主键后缀，不应重复建索引。程序不会自动修改业务索引。事务/查询使用已有 `agent.bridge.query-timeout-seconds`（默认2秒），超时明确失败。

当前完成的是本地实现与离线验证。现有正式数据库上的查询计划、全量SQL对账、真实语义分析效果和服务器部署验收仍需在对应环境完成。
