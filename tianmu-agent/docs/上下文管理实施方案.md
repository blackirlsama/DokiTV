# 上下文管理实施方案

日期：2026-10-24。状态：代码核查后的实施提案，本文不表示功能已实现。

## 当前实现和缺口

- `MemoryBuilder` 对历史按序排序，保留最多 8 条近期消息，将更早消息逐条截取到 500 字符，并限制历史正文为 16000 字符。所谓 olderSummary 是确定性摘录，不是语义摘要。
- `MysqlRunRepository` 读取最多 10 个历史可见轮次；按请求开始时的 historyVersion/historyBeforeTurn 形成快照，结合当前视频权限过滤；Redis 是可回源的近期缓存。
- `PreparedTask` 固定任务条件、来源、资源版本和工具边界；澄清有独立的结构化续接流程，应沿用这一事实来源。
- `AgentRuntime` 每轮将累计 ToolResult 放入 ModelContext；CONTEXT 变换后有序列化大小限制，没有模型窗口预算和固定降级流程。
- `TransformInvariants` 要求历史与当前问题不变，且保护工具事实字段。投影应形成独立契约，不能用普通 Hook 任意截断事实。
- `DeepSeekHarnessModel` 将 memory、query、preparation、任务条件、工具定义和结果放入请求；`DeepSeekPreparationModel` 也发送历史。当前没有覆盖这些实际请求的统一输入预算。

## 数据边界

| 层 | 权威来源 | 模型可见内容 | 生命周期 |
|---|---|---|---|
| 可信规则与能力 | 服务端 Prompt、Skill、工具注册表与授权 | 必要规则和当前可用 Schema | 任务内固定版本 |
| 当前任务 | 原始问题、服务端校验的 Specification、显式澄清 | 当前问题、已确认条件、待补字段、条件来源 | 单次请求；澄清通过新请求显式续接 |
| 会话历史 | MySQL 已提交消息 | 有版本、有角色的近期原文和旧轮次摘录 | 每次请求捕获快照 |
| 执行工作集 | 受控工具调用记录与原始证据 | 有界工具结果视图、事实及受控引用 | 当前任务 |
| 长期记忆 | 后续独立设计 | 首期不自动召回 | 需单独定义授权、有效期及删除 |

历史和工具内容均为不可信数据。历史不能授予工具权限、覆盖当前问题，或把旧指标直接升级为本次查询证据。上下文只存可观察结果与条件，不保存模型内部思维链。

## 目标调用链

请求身份校验 → 固定历史快照 → 构建历史视图 → 预处理输入预算 → 校验任务条件 → PreparedTask → 收集工具视图 → 上下文规划 → CONTEXT 扩展 → 最终请求序列化与预算复核 → 模型。

主循环和收尾复用同一预算流程；预处理复用计量与硬门控，按其模型使用独立策略。预算不得通过 Hook 或收尾路径绕开。

## 首轮实施范围

### 1. 历史视图策略

增加不可变 `MemoryPolicy`，明确最近原文条数、旧摘录额度、历史总额度和版本。数据库读取上限与投影上限分别配置，并设置合法范围。

完整轮次以相同 runId、USER/ASSISTANT 角色和服务端序号识别，不能仅靠列表奇偶位置配对。缺失回复的轮次不作为完整问答进入模型。预算不足时优先处理较旧轮次；保留来源标识、顺序、快照版本和明确的裁剪标记。

当前问题放在历史之外，用户已确认的业务条件沿用 Specification/澄清记录，不从摘录中自动认定为已确认。若要支持“那个视频”“改成前天”，必须增加候选条件解析和服务端校验，歧义时澄清。

### 2. 输入预算与固定门控

新增 `ContextBudgetPolicy`、`ContextSizer` 和 `ContextBudgetGuard`。策略按模型角色声明窗口、输出预留、协议余量和安全余量，不推断供应商真实窗口。

可用输入 = 配置窗口 − 输出预留 − 协议余量 − 安全余量。

计量完整实际消息，覆盖 system、当前问题、历史、工具 Schema、结果、preparation 和任务条件；不能只数 ModelContext.message 或历史正文。优先采用匹配模型的 tokenizer；回退估算必须记录方法和策略版本，明确其不能保证精确 Token 数，并保留最终传输字节上限。

在插件之后、HTTP 请求发出之前再次检查。不可缩减内容已经超限时，使用稳定错误码 `CONTEXT_BUDGET_EXCEEDED` 结束，禁止隐式吞掉异常后继续请求模型。窗口预算与累计调用/Token/费用预算分别管理。

### 3. 工具结果视图

增加 `ToolResultProjector` 和独立 `ToolObservationView`，保留 observationId、工具名、参数指纹、状态、证据/产物引用、口径、完整性及 originalSize/compacted/truncated。视图变化不修改 EvidenceStore 的原始事实。

新工具输出优先声明可保留的结构化字段。没有压缩契约的结果超限时明确拒绝，不能随意剪断 JSON，也不能声称 read_result 已具备分页读取大结果的能力。

降级顺序：压缩较旧且可恢复的工具正文 → 缩减较旧历史轮次 → 移除可选参考片段 → 明确拒绝。保护当前问题、可信规则、权限边界、必要 Schema、当前必要结果与证据口径。若使用工具协议消息，调用和结果必须成对投影。

### 4. 大结果与受控读回

对接已有私有对象存储和产物元数据前，核实其是否支持本次工具结果的归属、哈希、有效期、容量和分页语义。工具入口在分配巨大对象之前限制查询规模；压缩不能代替查询端的数量与字节上限。

读回需重新鉴权，限制单次页大小，返回明确的完整性与下一页信息；过期或撤权不能回退为直接暴露对象键。该阶段通过后，才启用依赖可恢复引用的工具压缩。

## 验收标准

| 场景 | 必须满足 |
|---|---|
| 稀疏序号、缺失助手回复、乱序历史 | 不错配轮次，按服务端序号排序，原始消息不变 |
| 超长中文、JSON、emoji | 有界输出；不产生半个代理对；所有正文与元数据按实际发送结构计量 |
| 历史中的提示注入 | 不改变任务权限或已确认条件，仍受工具端检查 |
| 工具结果压缩 | 原始证据、数字、口径和完整性不变，引用可授权读回 |
| 核心输入自身超限 | 不发 HTTP 请求，返回稳定预算错误 |
| CONTEXT 插件扩大输入 | 最终门控拒绝超限输入 |
| 预处理、主循环、收尾 | 均执行计量；收尾仍遵守原请求截止时间 |
| 会话并发、撤权、缓存回源 | 使用既定快照；不混入后续轮次；当前权限有效 |
| Trace | 仅记录策略版本、计量方法、分项大小、压缩数量和错误码，不记录正文或凭证 |

实施顺序为：历史策略和完整轮次校验 → 全调用路径预算门控 → 工具视图与受控读回 → 真实模型评测。每步独立提交并验证，不把长期语义记忆、RAG 或多 Agent 作为首轮依赖。
