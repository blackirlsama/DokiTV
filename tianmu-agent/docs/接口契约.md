# 接口契约 v0.7（HTTP 兼容字段扩展）

v0.6 保持 HTTP 路径和 SSE 事件名，Snapshot 新增字段，内部 Java ToolContext 与 StopReason 包位置有调整。Skill、Prompt 和工具声明改为 classpath 资源；新增工具实现 AgentTool，新增 Skill 按《工程目录与扩展规范》配置。工具参数在变换后按声明 Schema 校验。

v0.7 新增可选 sessionId/replyToRunId 与 Idempotency-Key。原单字段请求继续有效。Snapshot 新增 sessionId、turnSeq。持久化启动和新接口见 [持久化存储接入](持久化存储接入.md)。

统一 POST 入口执行 FAQ → 确定性前置校验 → 并行预处理 → PreparedTask 或直接澄清 → Harness，详见 [统一入口与并行预处理](统一入口与并行预处理.md)。
FAQ 同样返回任务的 202，状态/SSE 返回最终答案，不新增同步直答响应协议。

## HTTP

开发地址 `http://127.0.0.1:8201`。所有接口需 `Authorization: Bearer <credential>`。
demo 凭证为 demo-alice 和 demo-bob；这些只是本地协作身份，不是生产认证。

| 方法与路径 | 输入 | 输出 |
|---|---|---|
| POST /api/agent/runs | JSON：`{"message":"查询视频1001昨天的弹幕数"}` | 202 + Snapshot + Location |
| GET /api/agent/runs/{runId} | UUID | 200 + Snapshot |
| GET /api/agent/runs/{runId}/events | 可选 Last-Event-ID 事件序号 | text/event-stream |
| POST /api/agent/runs/{runId}/cancel | 无请求体 | 200 + Snapshot |
| GET /api/agent/runs/{runId}/evidence/{evidenceId} | 证据 ID | 200 + Evidence |

message 不得为空，最长 2000 字符。任务和证据只对创建者可见，读取时重新检查身份范围。
如果资源范围发生收缩，旧任务会拒绝读取，直到明确实现更细粒度的结果过滤。
未提供 Idempotency-Key 时，每次 POST 创建新任务；提供后按拥有者及请求指纹去重，冲突返回 409。

Snapshot（Java record 字段名即 JSON 字段名）：

```json
{
  "runId": "00000000-0000-0000-0000-000000000001",
  "sessionId": "00000000-0000-0000-0000-000000000002",
  "turnSeq": 1,
  "status": "SUCCEEDED",
  "createdAt": "2026-10-20T00:00:00Z",
  "steps": 3,
  "traceId": "32 lowercase hex",
  "answer": {"text": "【模拟数据】...", "evidenceIds": ["ev_example"]},
  "clarification": null,
  "errorCode": null,
  "stopReason": "ANSWER",
  "modelCalls": 3,
  "preparationCalls": 3,
  "totalModelCalls": 6,
  "route": "HARNESS",
  "faqId": null,
  "faqVersion": null,
  "preparation": {
    "originalQuery": "查询视频1001昨天的弹幕数",
    "query": "查询视频1001昨天的弹幕数",
    "emotion": "NEUTRAL",
    "degradedStages": [],
    "skippedStages": []
  }
}
```

示例省略新增 task 对象。HARNESS 路由在进入循环前固定 task，含 runId、originalQuery、query、businessDate、timezone、scope、preparation、specification(type/conditions/provenance)、resourceVersions、allowedTools、deadline、maxModelCalls。FAQ/直接澄清的 task 为 null；准备中也可为 null。该内部任务包仅向拥有者返回，外部模型仅接收必要条件，不发送完整 scope。

响应头增加 X-Trace-ID；任务 Snapshot 的 traceId 对应创建时的 Trace。其他读取请求可拥有自己的 HTTP Trace。
Trace 与 Hook 的扩展契约见《Harness-Trace与Hook设计》。

状态为 QUEUED、RUNNING、SUCCEEDED、NEEDS_INPUT、FAILED、CANCELLED。
route 为 FAQ、CLARIFY、HARNESS；准备尚未完成或此前失败时可为 null。
FAQ 的 evidenceIds 为空，并提供 faqId / faqVersion、stopReason=FAQ_ANSWER；普通业务答案仍要求指标证据。
modelCalls 保持只统计 Harness 调用（含收尾）；preparationCalls 统计已启动的三个准备分支，totalModelCalls 为两者之和。默认共用 16 次请求上限；均为尝试计数，尚无 Token/费用账本。
最后四种为终态；终态不可再被晚到的模型响应覆盖。
NEEDS_INPUT 表示本次任务已经结束。persistent 模式可带 sessionId/replyToRunId 显式创建续接任务，当前支持单视频弹幕条件。一般历史背景会传给模型，但不承诺通用指代理解。

HTTP 层身份/请求错误直接返回非 2xx；异步执行错误写入 FAILED 状态及 ERROR / DONE 事件。
不要只通过创建接口的 202 判断任务成功。

## SSE

事件体统一为 `sequence / type / data / at`。SSE 的 id 与 sequence 相同，从 1 递增。

```text
id:1
event:PROGRESS
data:{"sequence":1,"type":"PROGRESS","data":{"run_id":"...","stage":"queued"},"at":"..."}
```

| 事件 | data | 行为 |
|---|---|---|
| PROGRESS | stage、可选 tool | 展示进度，不承诺输出内部推理过程 |
| CLARIFICATION | message | 请求补充信息，随后 DONE |
| ANSWER | text、evidenceIds | 已经过首期引用归属校验的最终答案，随后 DONE |
| ERROR | code | 执行失败，随后 DONE |
| ABORT | reason | 用户取消，随后 DONE |
| DONE | run_id、status | 每任务唯一终态事件 |

首期没有 ANSWER_DELTA、ARTIFACT_READY；新增这两类事件前先明确校验和交付时序。
同进程内可使用 Last-Event-ID 重放未读事件。游标小于 0 或超过当前序号会被拒绝。
断线后任务继续运行，需要主动调用 cancel 才取消。
默认内存模式重启不可恢复；persistent 模式从 MySQL 回放，事件超过保留期返回 EVENTS_EXPIRED/410，仍可查询保留期内的最终 Snapshot。

浏览器原生 EventSource 无法直接设置自定义 Authorization 头；当前前端使用 fetch 流读取，并自行管理
Last-Event-ID 和重连，或由后续统一登录方案提供同源安全 Cookie。不要把 Bearer 凭证放到 URL 查询串里。

## 模型与工具

`ModelPort` 收到 ModelContext：message、businessDate、AccessScope、activeSkills、observations、availableTools、remainingSteps、finalizing、systemDirective、preparation、task。
message 是准备层接纳的执行 Query，preparation 保留原问题、情绪和降级标记。CONTEXT 插件不能修改 preparation、task 或可信范围。
finalizing=true 时工具目录必须为空，适配器按 systemDirective 进行一次无工具收尾；总截止时间不延长。
模型和查询端口支持 CallControl，用于传递截止时间及取消；真实适配器必须落实到网络调用。
availableTools 包含工具描述与 JSON Schema；真实适配器应转成选用模型的工具调用协议。
模型只返回一个 Decision，三选一：

- TOOL：ToolCall(name, arguments)。由 Runtime / Dispatcher 执行。
- CLARIFY：clarification 非空。
- ANSWER：Answer(text, evidenceIds)。不能引用当前任务不存在的证据。

ToolResult 新增可选 terminalAnswer；工具声明最终答复时仍走正常答案校验和交付 Hook，不允许工具自己向客户端发送。
变换结果时优先使用 withData，以保留 terminalAnswer。接口保留旧构造器便于适配迁移。

预处理端口：FaqPort.find(Input, CallControl) 返回 Optional<FaqAnswer>；PreparationModelPort 的 emotion / clarify / rewrite 接收相同 Input 并独立并发执行。
Input 中 scope 由服务端认证得到。默认 FAQ 等待 300ms、并行阶段共享 2 秒，均受请求总截止时间限制；具体降级和错误分类见入口设计文档。

工具注册与执行校验均在 `ToolDispatcher`；全局工具与当前激活 Skill 的工具分别暴露。

| 工具 | 参数（只接受列出的字段） | 返回 |
|---|---|---|
| list_skills | `{}` | 名称、描述列表 |
| read_skill | `{"name":"video-metrics"}` | 完整 Skill 与工具 Schema，并激活工具 |
| read_result | `{"result_id":"ev_..."}` | 当前任务拥有的结构化证据 |
| query_video_metrics | `{"video_id":1001,"date":"2026-10-19","metric":"bullet_count"}` | 指标值、版本、来源、数据时间、证据 ID |

query_video_metrics 必须先激活 video-metrics；日期限定北京时间最近 30 个已结束自然日。
AccessScope 是服务端内部参数，不在模型可填写的工具 Schema 中。
参数、权限、任务条件错误立即结束。仅 TOOL_CALL_TIMEOUT / TOOL_TEMPORARY_ERROR 可由后续模型轮次受控再尝试，连续同工具失败受上限保护；没有透明网络自动重试。

## 业务查询契约

`BusinessQueryPort.query(MetricQuery, AccessScope)` 接收 videoId、date、metric。
真实适配器必须在业务查询服务端再次校验权限，不能只依赖 Agent 的前置检查。
返回 MetricData：

| 字段 | 含义 |
|---|---|
| videoId / date / metric | 必须与本次请求相符 |
| value | 指标数值；无数据覆盖时不能伪装成 0 |
| metricVersion | 统计口径版本 |
| source | 可识别的数据来源 |
| dataAsOf | 数据覆盖/同步水位；不能随意用当前请求时间替代 |
| timezone | Asia/Shanghai |
| complete | 对请求时间范围是否完整；首期不完整结果会拒绝交付 |
| demo | 是否为合成数据 |

当前 demo 适配器始终返回 128 和 synthetic-fixture，dataAsOf 是合成快照的生成时刻。
真实适配器应建立正确的水位语义；不能复用演示中的 Instant.now() 实现。

ToolDispatcher 登记 Evidence(id, runId, owner, data)。ID 是引用句柄，不是授权令牌。
当前实现验证引用存在且属于任务/用户，尚不能保证文字结论与每个数值、比较关系、因果描述相符。
同学实现真实模型后，必须扩展 AnswerVerifier 或限制为基于结构化指标的模板渲染。

## 错误码

| 类型 | 代表码 | 处理 |
|---|---|---|
| 身份 / 范围 | UNAUTHORIZED、FORBIDDEN | 不重试，重新登录或检查范围 |
| 查询与状态 | RUN_NOT_FOUND、RESULT_NOT_FOUND | 检查过期、重启、所属任务 |
| 输入 | INVALID_REQUEST、INVALID_ARGUMENTS、DATE_OUT_OF_RANGE、TASK_CONSTRAINT_VIOLATION | 修改请求或工具参数 |
| 能力 | TOOL_NOT_AVAILABLE、SKILL_REQUIRED、SKILL_NOT_FOUND、TOOL_NOT_FOUND、METRIC_UNSUPPORTED | 修复模型路由或能力配置 |
| Hook | HOOK_REJECTED、HOOK_TRANSFORM_FAILED、HOOK_TRANSFORM_INVALID、HOOK_PAYLOAD_TOO_LARGE | 排查策略/变换插件，不自动交付原始数据 |
| 执行 | NO_PROGRESS、STEP_LIMIT、MODEL_CALL_BUDGET_EXCEEDED、DEADLINE_EXCEEDED | 查看任务轨迹，调整任务或预算 |
| 结果 | INVALID_DECISION、INVALID_ANSWER、INVALID_EVIDENCE | 拒绝交付，排查适配器 |
| 资源 / 内部 | CAPACITY_EXCEEDED、QUEUE_FULL、INTERNAL_ERROR | 调查容量或内部实现；不返回敏感异常 |

## 并发、部署与扩展限制

执行池核心 2、最大 4、队列 32；任务容量 200。这些是本地协作的资源上限，不是吞吐承诺。
总时限从任务创建起计时并由独立定时器取消：demo 为 30 秒，DeepSeek profile 为 120 秒；适配器仍需落实 CallControl。
SSE 已由独立发送池推送，不在任务状态锁或 Agent worker 上发送；最多 64 个订阅。尚无心跳和完整生产背压策略。
persistent 模式已落库，但每个数据库仅允许一个写实例；尚无多写实例并行调度和水平扩展机制。
后续生产配置必须替换 demo 身份、只读凭证、调用超时、限流、持久化和审计。

## Java 工具上下文迁移

ToolContext 现在是受限接口，提供 runId/scope/businessDate/checkpoint、Skill 读取与显式激活、工具定义、证据读取/登记、受控 query。移除完整 RunState/Harness 暴露；普通工具不具备 canActivateSkills 能力时无法激活 Skill。StopReason 位于 com.Tianmu.agent.core。

## 持久化错误码

- STORAGE_UNAVAILABLE / OBJECT_STORE_UNAVAILABLE / ARTIFACT_UNAVAILABLE：503；同一幂等键重试，不推断已完成。
- IDEMPOTENCY_CONFLICT / CLARIFICATION_CONFLICT / STORAGE_FENCED：409。
- SESSION_NOT_FOUND：404；EVENTS_EXPIRED：410。

正式消息、产物和会话删除接口及示例见《持久化存储接入》。历史只包含正式用户/助手消息，工具结果保留在证据或对象中。
